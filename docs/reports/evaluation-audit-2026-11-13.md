# Evaluation pipeline audit: November 13, 2026

The audit identified defects that can change benchmark scores or contaminate the interpretation of Critic feedback. Historical scores must be treated as outputs of the earlier pipeline; they do not establish model accuracy or a causal Critic advantage.

| Finding                                                                                                                                 | Correction                                                                                                                                     | Verification                                                                                                |
| --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |

Coder calls use one model turn, no tools, no project memory, and an empty conversation history. Each Critic call also starts from an empty history and receives only the problem, candidate code, setup, and observed failures supplied in its prompt. Critic feedback is then explicitly added to a fresh Coder request. Blind retries receive only the original problem prompt.

The selected comparison for subsequent work is single-call LLM generation versus generation with iterative Critic feedback. Additional Coder attempts and Critic calls are part of that treatment, so an accuracy gain alone does not isolate the value of Critic reasoning from extra inference budget.

A new candidate pool uses sanitized MBPP positions 101–200 (offset 100, limit 100). This pool is not assumed to have an official difficulty label. Its initial single-call failures define an operationally difficult subset for inspecting Critic recovery. Report both the full-pool score and conditional recovery; selecting failures does not estimate general benchmark accuracy by itself.

The test runner executes generated Python as a local subprocess with a timeout. It is an evaluation runner, not a security sandbox. No reference solution is supplied to either model.
